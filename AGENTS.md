# AGENTS.md

## Project

attest is an offline C2PA Content Credentials verifier and provenance tool. It
reads the JUMBF manifest store out of a JPEG, PNG, WebP, or raw JUMBF file,
decodes the CBOR claim, verifies the COSE_Sign1 signature against the `x5chain`
with WebCrypto, verifies every assertion hash, verifies the `c2pa.hash.data`
hard binding over the asset bytes with exclusions, walks the certificate chain,
evaluates a trust list, and reports a validation state with stable issue codes.
It also emits a portable provenance card and can anchor cards in a JSON Lines
registry. There is no server, no upload, no account, no network call, and no
telemetry. Output is human-readable text or stable JSON. The same engine runs in
Bun and in the browser.

## Commands

- `bun install` — install dependencies.
- `bun test` — run the test suite. The repository currently ships no test files,
  so `bun test` reports no matching files and exits non-zero.
- `bun run typecheck` — `tsc --noEmit`.
- `bun run build:site` — bundle `src/index.ts` into `site/assets/studio.js`
  (esbuild, IIFE, global `Attest`).
- `bun run check:site` — validate every `site/*.html`: exactly one `<h1>` and
  one `<main>`, a skip link whose fragment matches an element id, only classes
  defined in `lens.css` or `theme.css`, and only local links that resolve.

## Layout

- `src/` — implementation. Must stay browser-safe (no `node:` imports and no
  Node-only globals); the same code runs in the browser bundle and the CLI.
- `src/cli.ts` — the `attest` CLI entry point.
- `src/mcp.ts` — the MCP server entry point and its three tool definitions.
- `src/verify.ts` — the verification pipeline, issue codes, and validation state.
- `src/jumbf.ts` — container location (JPEG/PNG/WebP/raw) and the JUMBF box model.
- `src/cbor.ts` — the CBOR decoder and encoder.
- `src/cose.ts` — COSE_Sign1 parsing and signature verification.
- `src/x509.ts` — DER certificate parsing, public-key import, chain signatures.
- `src/der.ts` — the DER reader.
- `src/bytes.ts` — byte readers and hex/base64 helpers.
- `src/crypto.ts` — the small WebCrypto wrapper.
- `src/trust.ts` — trust-list parsing and evaluation.
- `src/report.ts` — text and JSON reports and the card projection of a manifest.
- `src/resolve.ts` — provenance cards, the card id, and the JSON Lines registry.
- `src/index.ts` — the public API surface, and the esbuild entry point.
- `spec/SPEC.md` — the normative description of what is verified.
- `fixtures/` — the conformance corpus. `fixtures/C2PA-signed.jpg` is a signed
  JPEG from the `contentauth/c2pa-rs` test fixtures.
- `site/` — static assets and `site/assets/` (the shared design system, the
  per-tool theme, self-hosted fonts, and the generated browser bundle).
- `scripts/` — `build-site.mjs` and `check-site.mjs`.
- `install.sh` — the installer script for the `attest` binary.
## Conventions and hard rules

- `src/` except `src/cli.ts` and `src/mcp.ts` must stay browser-safe: no `node:`
  imports and no Node-only globals, because `scripts/build-site.mjs` bundles
  `src/index.ts` into `site/assets/studio.js`. Use WebCrypto (`crypto.subtle`),
  `TextEncoder`, and standard web APIs. Node-only code belongs in `src/cli.ts`
  (which imports `node:fs/promises`, `node:fs`, and `node:path`) and in
  `src/mcp.ts` (which uses `Bun.stdin`).
- `site/assets/lens.css` is a shared design system copied byte-identical across
  the suite. Do not edit it. Per-tool styles go in `site/assets/theme.css`.
- `site/assets/studio.js` is generated by `scripts/build-site.mjs`. Edit `src/`,
  then run `bun run build:site`; never hand-edit the bundle.
- The CLI contract is stable: the commands `inspect`, `verify` (with the `check`
  alias), `card`, `anchor`, `resolve`, and `mcp`, and exit codes `0` (valid, or
  nothing to report), `1` (invalid, untrusted under `--require-trusted`,
  unsigned, or a card miss), `2` (usage or unreadable format), and `3` (I/O
  error). Adding a command or flag is additive; changing an existing exit code
  is not.
- The MCP tool names are stable: `provenance_verify`, `provenance_inspect`, and
  `provenance_card`. Adding a tool is additive and does not change the others.
- `fixtures/` is the conformance corpus. `fixtures/C2PA-signed.jpg` is the
  reference asset; do not regenerate or edit a fixture silently. If a fixture
  must change, say so in the change and keep the old bytes reachable.
- The library is offline by design. Never add network access, remote manifest
  fetching, OCSP/CRL fetching, or telemetry to `src/`.
