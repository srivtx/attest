Reference

Usage

The same engine runs from the command line, from TypeScript, from an MCP-capable agent, and in the browser. Every surface reads bytes and returns the same verification result.

Install

install 
# one-line install (drops an `attest` binary on PATH)$ curl -fsSL https://raw.githubusercontent.com/srivtx/attest/main/install.sh | sh# run once, without installing$ bunx github:srivtx/attest#main --help# pin a branch, tag, or commit$ curl -fsSL https://raw.githubusercontent.com/srivtx/attest/main/install.sh | sh -s v0.1.0# add as a project dev dependency$ bun add -d github:srivtx/attest

attest is not published to npm, and it requires Bun. The install script runs bun add -g github:srivtx/attest#<ref>; bunx github:srivtx/attest#main runs the latest main without installing anything.

Commands

Six commands. check is accepted as an alias for inspect and verify.
CommandDescription
attest inspect <file> [options]Verify and print the full report: signature, chain, actions, ingredients, hard binding, and every issue.
attest verify <file> [options]Verify and print a one summary line, unless --verbose. The exit code is the answer.
attest card <file>Print a portable provenance card as JSON.
attest anchor <file> --registry <path>Append a provenance card to a registry file.
attest resolve <hash|file> --registry <path>Look up a card by SHA-256, or re-verify a file against the card already in the registry.
attest mcpRun the MCP server over stdio.

Flags

Every flag. A value flag takes the next argument — write --trust file, not --trust=file.
FlagDescription
--trust <file>A trust list: a C2PA trust list JSON document or a PEM certificate bundle.
--require-trustedTreat an untrusted signer as a failure. Sets assertTrusted; it only bites when a trust list is supplied.
--jsonPrint a machine-readable JSON document to stdout.
--verbose, -vInclude per-assertion detail and certificate validity windows.
--quiet, -qSuppress output; rely on the exit code.
--registry <path>The registry file for anchor and resolve, in JSON Lines form.
-h, --helpShow the help text and exit.
--versionPrint the version and exit.

Verify, valid and tampered

verify without --verbose prints a single line. Run against the signed fixture and against a tampered copy, the difference is the hard binding.

attest verify 
$ attest verify fixtures/C2PA-signed.jpgvalid: C.jpg — signature valid, hard binding matchedexit 0$ attest verify tampered.jpginvalid: C.jpg — signature valid, hard binding mismatchexit 1

Exit codes

The exit code is the CI gate.
CodeMeaning
0Valid, or nothing to report. An untrusted signer also exits 0 unless --require-trusted is set.
1Invalid, untrusted with --require-trusted, unsigned (no manifest), or a resolve mismatch.
2Usage error: a missing argument, an unknown option or command, or --registry omitted where it is required.
3I/O error: an input file could not be read, or a trust list could not be parsed.

A file that cannot be read is never reported as clean: it exits non-zero, so a gate cannot pass on input the tool did not understand.

Provenance cards and the registry

card prints a portable, self-describing record of one verification. anchor appends that card to a registry; resolve looks one up and re-verifies a file against it.

The registry is JSON Lines: one card per line. Blank lines and lines that are not attest/card/1 are skipped, so a registry can sit next to other data and survive hand edits.

MCP server

attest mcp speaks the Model Context Protocol over stdio, so an agent can verify provenance without a shell. Each tool takes the file bytes as base64 in data. There is no network access from the server.

{
  "mcpServers": {
    "attest": {
      "command": "bunx",
      "args": ["github:srivtx/attest#main", "mcp"]
    }
  }
}
The three MCP tools.
ToolArgumentsReturns
provenance_verifydata (string, base64, required), name (string, optional)A one-line summary followed by the text report.
provenance_inspectdata (string, base64, required), name (string, optional)The full verbose report, including every assertion.
provenance_carddata (string, base64, required)The attest/card/1 card and the state, as JSON.

JavaScript API

The engine is exported from src/index.ts and is browser-safe: no node: imports, so the same code runs in Bun and in a page. The built browser bundle exposes the same names on the global Attest.

import { verifyBytes, formatReport, formatJson, summarize, toCard } from "attest";

const bytes = new Uint8Array(await file.arrayBuffer());
const asset = await verifyBytes(bytes);

console.log(summarize(asset));           // one line, e.g. the verify output
console.log(formatReport(asset));        // the text report
console.log(formatJson(asset, 2));       // the stable JSON document
const card = toCard(asset);              // an attest/card/1 object

Pass a trust list and ask for it to be enforced by handing verifyBytes the options directly.

import { verifyBytes, parseTrustList } from "attest";

const trustList = await parseTrustList(pemText, "roots.pem");
const asset = await verifyBytes(bytes, { trustList, assertTrusted: true });

In a page, the bundle is a classic script that defines Attest; the landing page verifier calls Attest.verifyBytes, Attest.formatReport, Attest.summarize, and Attest.formatJson. Also exported: hashWithExclusions, sha256, locateManifest, parseManifestStore, parseTrustList, evaluateTrust, cardId, serializeCard, parseRegistry, resolveByHash, and matchCard.

Trust lists

A trust list is a list of signers you have decided to accept. attest matches a chain link when its SHA-256 fingerprint equals the entry's cert_sha256, or when its subject name equals the entry's subject exactly. Any certificate in the chain may match.

Two formats are accepted. A JSON document may be a top-level array or an object with a trusted_list (also trusted, allowed, entries, or certificates) array of entries. Each entry may carry cert_sha256 (aliases certSha256, sha256, fingerprint; colons are stripped) and/or subject (alias subject_dn); an issuer field is read but is not used for matching.

{
  "trusted_list": [
    { "subject": "C=US, ST=CA, L=Somewhere, O=C2PA Test Signing Cert, OU=FOR TESTING_ONLY, CN=C2PA Signer" },
    { "cert_sha256": "68e2ccccf0ee0529528e931abd0f68ec8077238da4e041d344d900498a2b953c" }
  ]
}

The other format is a PEM bundle: every certificate in the file becomes an entry keyed by the SHA-256 of its DER, together with its subject and issuer.

trust 
# a JSON trust list$ attest verify photo.jpg --trust trust-list.json --require-trusted# a bundle of PEM certificates$ attest verify photo.jpg --trust roots.pem --require-trusted# untrusted, with a list that does not name the signeruntrusted: C.jpg — signature valid, hard binding matchedexit 1

With no trust list at all, the trust status is unknown, not untrusted. That means --require-trusted on its own does not fail a file whose signer you never vouched for; supply --trust to make the check meaningful.
